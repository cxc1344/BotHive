# BotHive 0.7.0 调研与版本方案

写于 2026-11-24，是 0.7.0「蜂巢自治」的设计依据。

## 一、竞品要点

| 产品 | 发布时间 | 在哪执行 | 最值得学的设计 | 主要短板 |
|---|---|---|---|---|
| Grok Bot（xAI） | 2026-08 测试版 | 一台共享云端电脑，所有 Bot 共用 | 例行任务可由事件触发（Slack / GitHub / 邮件 / Webhook），创建前先确认六件事，有「测试」按钮和运行记录；示教录制；无人值守的审批约 30 分钟过期；主 Bot 汇总所有 Bot | 额度烧得快；Bot 之间没有隔离；不能选模型 |
| OpenAI dots | 2026-09-29 | 每个 dot 一台云端 Linux + Chrome，可以接管 | 四档规则，只能收紧；审查器放在 dot 自己改不到的地方；密码与转账强制交还给人；Activity View | 确认太多（一件事要点三次）；慢；记忆不能查看 |
| Claude Duet | 2026-10-21 研究预览 | 云端虚拟机 | 发送 / 付款 / 签署 / 删除必须批准；审批不阻塞其余工作；有些操作批准了也不做；防泄露分类器；早报先把第一步做好；数字都注明来源 | 定时检查会漏急事；浏览器是黑箱；仅限美国 |
| Meta Muse | 2026-09-08 | 每个用户一台独立虚拟机 | 「执行」和「授权」分给两个智能体（Sentinel 审查出站）；一次性虚拟卡；完整审计记录 | 总在索要更多数据；默认用用户数据训练；仅限美国 |
| Operit AI | v1.12.2（2026-09） | 本机（Shizuku / Root） | ToolPkg 插件（版本、依赖、WASM）；A2A 1.0；token 账本 | 终端卡死；功能堆得多，Bug 也多 |
| Open-AutoGLM / 豆包手机 | 2025-12 起 | ADB 控制 / 系统级 | 敏感操作要确认，登录和验证码交给人；**只靠看屏点击操作超级应用这条路走不通**：豆包被 166 个应用拒绝，二代转向让应用自己提供 MCP | 被平台封禁 |

**BotHive 的护城河**：
- 每个 Bot 都是真正隔离的沙盒
- 浏览器看得见、能接管
- 能直接操作手机
- 模型自选、自带 Key
- 记忆可查可删
- 全球可用、免费、不拿你的数据训练

## 二、iOS 27 液态玻璃

核实下来，iOS 27 的改动主要是为了**更好读**：
- 用连续的透明度滑杆替代原来的「透明 / 着色」二选一
- 边缘加了暗边，高光更亮，对身后内容的柔化更强
- 内容滚到浮动栏下方时出现统一工具栏；27.3 测试版的滚动边缘渐隐更柔和
- 动画整体更快
- 有一篇报道说去掉了图标上随陀螺仪变化的反光（只有这一个来源）

BotHive 0.7.0 据此做了：连续强度滑杆、暗边与高光、顶部渐隐、动画加速，并且尊重省电模式和「移除动画」。真内容透镜（GraphicsLayer + RenderEffect）留到后续版本，因为华为在 HarmonyOS 7 收紧沉浸光感材质，正是出于性能和续航考虑。
